# Базовый минимум: LLM, Prompt Engineering, RAG и AI Agents

> [!abstract] Краткое описание  
> Обзор четырёх фундаментальных компонентов современных AI-систем: больших языковых моделей (LLM), промпт-инжиниринга, RAG-архитектуры и AI-агентов.
> 
> Материал объясняет, как модель обрабатывает информацию, как управлять её поведением, как подключать внешние источники знаний и как превращать генерацию текста в выполнение многошаговых задач.
> 
> Эти технологии являются фундаментом для понимания современных AI-приложений, автономных агентов и систем информационной безопасности на базе AI.

## 1. Общая архитектура современных AI-систем

Современные AI-приложения строятся не только вокруг языковой модели. В зависимости от задачи к ней добавляются инструкции, внешние источники знаний, инструменты и механизмы управления действиями.

Упрощённо архитектуру можно представить так:

```
                 USER
                   |
                   v
          PROMPT ENGINEERING
          Инструкции и контекст
                   |
                   v
                  LLM
          Обработка и генерация
                   |
          +--------+--------+
          |                 |
          v                 v
         RAG             AI AGENT
    Внешние знания      Планирование
    и поиск             и выполнение
          |                 |
          v                 v
    Vector Database     Tools / APIs
    Documents           External Systems
    Knowledge Base      Environment
                            |
                            v
                       ACTIONS
```

Основные компоненты:

|Компонент|Назначение|
|---|---|
|LLM|Обработка и генерация информации|
|Prompt Engineering|Управление поведением модели через инструкции|
|RAG|Получение внешней информации и передача её модели|
|AI Agent|Планирование и выполнение действий с использованием инструментов|

Важно понимать: это не четыре независимые конкурирующие технологии. Они дополняют друг друга и могут использоваться в рамках одной системы.

# PART 1. LARGE LANGUAGE MODELS (LLM)

## 2. Что такое языковая модель

Language Model (LM) — модель, которая оценивает вероятность появления следующего токена на основании предыдущего контекста.

Упрощённо:

P(wₜ | w₁, w₂, ..., wₜ₋₁)

То есть модель получает последовательность токенов и определяет, какой токен с наибольшей вероятностью должен следовать дальше.

Именно этот принцип лежит в основе генерации текста современными языковыми моделями.

### 2.1. Эволюция языковых моделей

Развитие языковых моделей прошло несколько основных этапов.

**1. Статистические модели (N-grams)**

Основывались на подсчёте частоты появления последовательностей слов.

Ограничения:

- Небольшой контекст.
    
- Отсутствие полноценного понимания семантики.
    
- Сложности с обработкой длинных последовательностей.
    

**2. Векторные представления (Embeddings)**

Слова начали представляться в виде числовых векторов в многомерном пространстве.

Примеры технологий:

- Word2Vec
    
- GloVe
    

Идея: слова с похожим значением имеют близкие векторные представления.

**3. Transformers**

Архитектура Transformer использует механизм Attention, позволяющий модели учитывать взаимосвязи между элементами последовательности.

Это стало основой современных LLM.

## 3. Large Language Models

LLM (Large Language Model) — большая языковая модель, обученная на значительных объёмах данных и способная решать широкий спектр задач с использованием естественного языка.

Основные характеристики:

- Большое количество параметров.
    
- Обучение на масштабных наборах данных.
    
- Способность обрабатывать контекст.
    
- Генерация естественного языка.
    
- Решение различных задач без отдельной модели для каждой задачи.
    

### 3.1. Параметры модели

Параметры (Parameters) — обучаемые числовые значения, определяющие поведение нейронной сети.

Примеры обозначений:

- 3B — 3 миллиарда параметров.
    
- 7B — 7 миллиардов параметров.
    
- 14B — 14 миллиардов параметров.
    
- 70B — 70 миллиардов параметров.
    

Количество параметров само по себе не определяет качество модели. Важны также архитектура, данные обучения, метод обучения и оптимизация.

### 3.2. Foundation Models

Foundation Model — фундаментальная модель, которая может служить основой для множества прикладных решений.

Примеры:

- ChatGPT
    
- Claude
    
- Gemini
    
- Qwen
    
- DeepSeek
    
- Llama
    

На базе таких моделей создаются:

- AI-ассистенты.
    
- Чат-боты.
    
- Системы анализа документов.
    
- Генераторы кода.
    
- AI-агенты.
    
- Корпоративные AI-системы.
    

### 3.3. Instruct Models

Instruct Model — модель, дополнительно обученная следовать инструкциям пользователя.

В отличие от базовой модели, которая преимущественно обучена предсказывать продолжение текста, instruct-модель адаптирована для выполнения заданий в формате запросов и ответов.

Один из методов такой адаптации — RLHF (Reinforcement Learning from Human Feedback).

RLHF использует человеческую оценку ответов для настройки предпочтительного поведения модели.

## 4. Токенизация (Tokenization)

LLM работает не непосредственно со словами, а с токенами.

Token — минимальная единица текста, используемая моделью при обработке информации.

Токеном может быть:

- Целое слово.
    
- Часть слова.
    
- Символ.
    
- Знак пунктуации.
    
- Пробел или другая текстовая единица.
    

Процесс:

```
Input Text
    |
    v
Tokenizer
    |
    v
Token IDs
    |
    v
LLM
    |
    v
Generated Token IDs
    |
    v
Detokenization
    |
    v
Output Text
```

Почему это важно:

1. Контекстное окно измеряется в токенах.
    
2. Стоимость использования API часто зависит от количества токенов.
    
3. Длина входного и выходного текста ограничена техническими параметрами модели.
    
4. Большой контекст увеличивает требования к вычислительным ресурсам.
    

Связанные заметки:

## 5. Основные параметры LLM

### Temperature

Определяет степень случайности при выборе следующего токена.

- Низкая Temperature — более предсказуемые ответы.
    
- Высокая Temperature — больше разнообразия и вариативности.
    

Для задач информационной безопасности, где важны повторяемость и точность, обычно предпочтительны более низкие значения, но это не гарантирует правильность ответа.

### Max Tokens

Определяет максимальное количество токенов, которое модель может сгенерировать в рамках ответа.

Важен для ограничения объёма результата и контроля затрат.

## 6. Мультимодальные модели (Multimodal AI)

Мультимодальные модели способны работать с различными типами данных:

- Текст.
    
- Изображения.
    
- Аудио.
    
- Видео.
    
- Таблицы.
    
- Код.
    

Вместо обработки только текстовой информации модель может анализировать несколько типов входных данных.

Примеры применения:

- Анализ скриншотов.
    
- Распознавание объектов.
    
- Анализ графиков.
    
- Обработка аудиозаписей.
    
- Анализ видеоматериалов.
    

### Применение в ИБ

Мультимодальные модели могут использоваться для:

- Анализа скриншотов фишинговых писем.
    
- Исследования подозрительных изображений.
    
- Анализа видеозаписей инцидентов.
    
- Изучения схем сетевой инфраструктуры.
    
- Анализа визуальных результатов сканирования.
    

**Security Considerations:**

- Возможность извлечения чувствительных данных из изображений.
    
- Prompt Injection через изображения и другие модальности.
    
- Утечка конфиденциальной информации.
    
- Ошибочная интерпретация визуальных данных.

# PART 2. PROMPT ENGINEERING

## 7. Что такое Prompt Engineering

Prompt Engineering — процесс проектирования и оптимизации инструкций для языковой модели с целью получения более точных, предсказуемых и полезных результатов.

LLM чувствительны к формулировкам и контексту.

Поэтому один и тот же вопрос, заданный разными способами, может приводить к различным ответам.

Основная задача Prompt Engineering — превратить пользовательский запрос в чёткое техническое задание для модели.

## 8. Структура эффективного промпта

Универсальная структура:

```
ROLE
Кем должна выступать модель?

TASK
Что необходимо сделать?

CONTEXT
Какая дополнительная информация доступна?

CONSTRAINTS
Какие ограничения необходимо соблюдать?

OUTPUT FORMAT
В каком формате предоставить результат?

AUDIENCE
Для кого предназначен ответ?
```

Пример:

```
ROLE:
Ты — специалист по информационной безопасности.

TASK:
Проанализируй предоставленные логи
и найди подозрительную активность.

CONTEXT:
Логи получены из Windows Event Log.

CONSTRAINTS:
Не придумывай отсутствующие события.
Отделяй факты от предположений.
Указывай степень уверенности.

OUTPUT FORMAT:
1. Краткое описание.
2. Подозрительные события.
3. Возможные техники ATT&CK.
4. Рекомендации по расследованию.
```

Важно: структурированный промпт повышает управляемость модели, но не гарантирует достоверность результата.

## 9. Основные техники Prompt Engineering

### 9.1. Zero-shot Prompting

Модель получает инструкцию без дополнительных примеров.

Пример:

```
Проанализируй лог и определи,
является ли событие подозрительным.
```

Используется для простых и типовых задач.

### 9.2. Few-shot Prompting

Модели передаются несколько примеров ожидаемого результата.

Пример:

```
Пример 1:

Input:
Failed login attempts: 2

Output:
Низкое количество неудачных попыток входа.

Пример 2:

Input:
Failed login attempts: 150

Output:
Возможная Brute Force активность.

Теперь проанализируй:
Failed login attempts: 80
```

Примеры помогают модели понять формат и логику ожидаемого ответа.

### 9.3. Chain-of-Thought (CoT)

Подход, при котором модель побуждают решать задачу последовательно, а не сразу выдавать итог.

Применение:

- Многошаговый анализ.
    
- Логические задачи.
    
- Сравнение нескольких гипотез.
    
- Анализ сложных сценариев.
    

Важно: запрашиваемое объяснение результата не следует автоматически считать достоверным отражением внутренних вычислений модели.

### 9.4. Zero-shot Chain-of-Thought

Модель получает инструкцию выполнять задачу последовательно без предварительных примеров.

Пример:

```
Проанализируй ситуацию последовательно.
Укажи использованные факты,
рассмотренные гипотезы и обоснование вывода.
```

### 9.5. Промптинг для мультимодальных моделей

При генерации изображений, видео и аудио используются дополнительные параметры.

Для изображений:

- Объект.
    
- Композиция.
    
- Освещение.
    
- Стиль.
    
- Ограничения.
    
- Формат результата.
    

Для видео:

- Субъект.
    
- Действие.
    
- Сцена.
    
- Камера.
    
- Динамика.
    
- Стиль.
    

Для аудио:

- Жанр.
    
- Темп.
    
- Настроение.
    
- Структура.
    
- Инструменты.
    
- Вокал.
    

## 10. Применение Prompt Engineering в ИБ

Примеры задач:

|Направление|Задача|
|---|---|
|SOC|Анализ событий безопасности|

### Security Considerations

Prompt Engineering тесно связан с безопасностью LLM.

Основные проблемы:

- [[Prompt Injection]] — внедрение вредоносных инструкций.
    
- [[Jailbreaking]] — обход ограничений модели.
    
- [[System Prompt Leakage]] — раскрытие системных инструкций.
    
- [[Indirect Prompt Injection]] — внедрение инструкций через внешние данные.
    
- [[Sensitive Information Disclosure]] — раскрытие конфиденциальных данных.
    

Ключевой принцип: системный промпт не является полноценным механизмом безопасности. Ограничения доступа и критические проверки должны реализовываться на уровне приложения и инфраструктуры.

# PART 3. RETRIEVAL-AUGMENTED GENERATION (RAG)

## 11. Ограничения обычных LLM

Обычная языковая модель имеет несколько существенных ограничений.

**1. Ограниченность обучающих данных**

Модель не получает автоматически информацию о событиях, произошедших после завершения её обучения.

**2. Галлюцинации (Hallucinations)**

Модель может генерировать правдоподобную, но недостоверную информацию.

**3. Ограниченное контекстное окно**

Количество токенов, которое модель может обработать за один раз, ограничено.

**4. Отсутствие прямого доступа к корпоративным знаниям**

Без дополнительных механизмов модель не знает содержимое внутренних документов, баз данных и закрытых репозиториев организации.

Для решения этих проблем используется RAG.

## 12. Что такое RAG

RAG (Retrieval-Augmented Generation) — архитектурный подход, при котором языковая модель получает дополнительную информацию из внешних источников непосредственно перед генерацией ответа.

Основная идея:

Не заставлять модель полагаться исключительно на знания, полученные при обучении, а предоставлять ей актуальный и релевантный контекст.

Источники данных:

- Документы.
    
- PDF.
    
- Базы данных.
    
- Веб-сайты.
    
- Репозитории кода.
    
- Корпоративные базы знаний.
    
- Техническая документация.
    

## 13. Основные компоненты RAG

### 13.1. Document Loading

Загрузка исходных документов в систему.

Примеры:

- PDF.
    
- DOCX.
    
- TXT.
    
- HTML.
    
- Markdown.
    
- CSV.
    

### 13.2. Chunking

Chunking — разделение больших документов на небольшие фрагменты.

Каждый фрагмент называется Chunk.

Зачем это нужно:

- Уменьшение объёма передаваемого контекста.
    
- Улучшение качества поиска.
    
- Более эффективное использование контекстного окна.
    
- Снижение затрат на обработку.
    

Основные подходы:

- Fixed-size Chunking — разделение по фиксированной длине.
    
- Semantic Chunking — разделение по смыслу.
    
- Recursive Chunking — последовательное разделение по структуре текста.
    

Дополнительно может использоваться Overlap — перекрытие соседних фрагментов для сохранения контекста.

### 13.3. Embeddings

Embedding — числовое векторное представление информации.

Документ или отдельный фрагмент преобразуется в вектор, который отражает его семантические характеристики.

Это позволяет находить документы по смыслу, а не только по точному совпадению слов.

### 13.4. Vector Database

Векторная база данных хранит векторные представления документов и позволяет выполнять поиск по близости векторов.

Примеры:

- FAISS.
    
- Chroma.
    
- Qdrant.
    
- Milvus.
    
- Weaviate.
    

### 13.5. Retrieval

Retrieval — этап поиска наиболее релевантных фрагментов по пользовательскому запросу.

Система:

1. Получает запрос.
    
2. Преобразует его в векторное представление.
    
3. Ищет близкие векторы.
    
4. Возвращает подходящие фрагменты.
    

### 13.6. Reranking

Reranking — дополнительное ранжирование найденных результатов.

Позволяет улучшить релевантность контекста, который будет передан языковой модели.

### 13.7. Generation

На заключительном этапе найденная информация объединяется с исходным запросом.

LLM использует полученный контекст для формирования ответа.

## 14. Как работает RAG

```
             DOCUMENTS
                  |
                  v
             LOADING
                  |
                  v
              CHUNKING
                  |
                  v
              EMBEDDING
                  |
                  v
           VECTOR DATABASE
                  |
                  |
USER QUERY ------+
                  |
                  v
              RETRIEVAL
                  |
                  v
              RERANKING
                  |
                  v
          CONTEXT AUGMENTATION
                  |
                  v
                 LLM
                  |
                  v
             FINAL ANSWER
```

Основные этапы:

1. Подготовка документов.
    
2. Разделение документов на фрагменты.
    
3. Создание эмбеддингов.
    
4. Сохранение в векторной базе.
    
5. Получение пользовательского запроса.
    
6. Поиск релевантной информации.
    
7. Передача найденного контекста в LLM.
    
8. Генерация ответа.
    

## 15. Варианты реализации RAG

### Naive RAG

Базовая реализация:

- Индексация документов.
    
- Поиск релевантных фрагментов.
    
- Передача найденных данных в LLM.
    

### Advanced RAG

Более сложная архитектура с дополнительными механизмами:

- Query Rewriting.
    
- Reranking.
    
- Удаление дубликатов.
    
- Фильтрация нерелевантных результатов.
    
- Оптимизация поиска.
    

### Modular RAG

Модульная архитектура, в которой компоненты поиска и обработки информации можно комбинировать и перестраивать под конкретную задачу.

Могут использоваться:

- Query Routing.
    
- Hybrid Search.
    
- Multiple Retrievers.
    
- Memory.
    
- Result Fusion.
    

## 16. RAG vs Fine-Tuning vs Prompt Engineering

|Подход|Что изменяется|Для чего используется|
|---|---|---|
|Prompt Engineering|Инструкция и контекст|Управление поведением|
|RAG|Доступные модели знания|Подключение внешней информации|
|Fine-Tuning|Параметры модели|Адаптация поведения и навыков|

Пример:

- Prompt Engineering: попросить модель отвечать в формате отчёта SOC.
    
- RAG: предоставить модели внутреннюю базу знаний организации.
    
- Fine-Tuning: адаптировать модель для определённого типа задач или формата.
    

Эти методы не исключают друг друга и могут использоваться одновременно.

## 17. Применение RAG в информационной безопасности

RAG особенно полезен там, где требуется анализировать большие объёмы специализированной документации.

Примеры:

**SOC Knowledge Assistant**

RAG подключается к:

- Runbooks.
    
- SOP.
    
- SIEM Documentation.
    
- Incident Reports.
    
- Detection Rules.
    

**Threat Intelligence Assistant**

Источники:

- MITRE ATT&CK.
    
- CTI Reports.
    
- IOC Databases.
    
- Threat Actor Reports.
    
- Security Advisories.
    

**Vulnerability Research Assistant**

Источники:

- CVE.
    
- NVD.
    
- Vendor Advisories.
    
- Security Bulletins.
    
- Технические исследования.
    

**DFIR Assistant**

Источники:

- Отчёты расследований.
    
- Методологии анализа.
    
- Внутренние процедуры.
    
- Артефакты инцидентов.
    

### Security Considerations

RAG создаёт собственную поверхность атаки.

Основные риски:

- [[Indirect Prompt Injection]] — вредоносные инструкции внутри документов.
    
- [[Data Poisoning]] — внедрение некорректных или вредоносных данных в базу знаний.
    
- [[Data Exfiltration]] — раскрытие данных через ответы модели.
    
- [[Broken Access Control]] — получение пользователем информации, к которой у него нет доступа.
    
- [[Sensitive Information Disclosure]] — утечка конфиденциальных документов.
    

Особенно важно учитывать, что найденный документ — это источник данных, а не доверенная инструкция для модели.

Защита должна включать:

- Контроль доступа на уровне документов.
    
- Проверку источников данных.
    
- Фильтрацию и обработку контента.
    
- Разделение инструкций и недоверенных данных.
    
- Контроль выдаваемых результатов.
    
- Логирование запросов.

# PART 4. AI AGENTS

## 18. Что такое AI Agent

AI Agent — система, использующая AI для достижения поставленной цели посредством анализа задачи, планирования, выбора инструментов и выполнения последовательности действий.

Главное отличие агента от обычной LLM заключается в способности взаимодействовать с внешней средой.

Обычная LLM преимущественно генерирует ответ.

AI Agent может:

- Анализировать задачу.
    
- Формировать план.
    
- Выбирать инструменты.
    
- Выполнять действия.
    
- Получать результаты.
    
- Оценивать промежуточные результаты.
    
- Корректировать дальнейшие действия.
    

Таким образом, агент превращает генерацию текста в управляемый процесс выполнения задач.

## 19. RAG vs AI Agent

RAG и AI Agent решают разные задачи.

|Характеристика|RAG|AI Agent|
|---|---|---|
|Основная задача|Получение знаний|Достижение цели|
|Поиск информации|Да|Может использовать RAG|
|Планирование|Обычно нет|Да|
|Вызов инструментов|Не является обязательным|Да|
|Многошаговые действия|Ограниченно|Да|
|Самокоррекция|Не является обязательной|Может поддерживаться|
|Взаимодействие со средой|Обычно отсутствует|Основная возможность|

Пример:

**RAG:**

Пользователь спрашивает: «Что означает событие Windows Event ID 4625?»

Система находит документацию и предоставляет объяснение.

**AI Agent:**

Пользователь просит: «Исследуй подозрительную активность в Windows-логах».

Агент может:

1. Получить логи.
    
2. Проанализировать события.
    
3. Найти подозрительные IP.
    
4. Обогатить информацию через внешние источники.
    
5. Сопоставить события с MITRE ATT&CK.
    
6. Сформировать отчёт.
    

## 20. Основные компоненты AI Agent

### 20.1. LLM — Brain

Центральный компонент, который обрабатывает информацию и принимает решения в рамках предоставленных инструкций.

Модель используется для:

- Интерпретации задачи.
    
- Выбора инструментов.
    
- Формирования промежуточных выводов.
    
- Генерации запросов.
    
- Подготовки итогового результата.
    

### 20.2. Tools — инструменты

Инструменты позволяют агенту взаимодействовать с внешними системами.

Примеры:

- API.
    
- Поисковые системы.
    
- Базы данных.
    
- Выполнение Python-кода.
    
- Файловая система.
    
- SIEM.
    
- EDR.
    
- Threat Intelligence Platforms.
    

### 20.3. Memory — память

Память позволяет сохранять информацию, необходимую для выполнения задач.

**Short-Term Memory**

Краткосрочная память:

- История диалога.
    
- Текущий контекст.
    
- Промежуточные результаты.
    
- Текущий план.
    

**Long-Term Memory**

Долгосрочная память:

- Сохранённые знания.
    
- Предыдущий опыт.
    
- Пользовательские предпочтения.
    
- Информация из внешних баз знаний.
    

Важно: RAG и Memory могут пересекаться технически, но не являются синонимами. RAG — способ поиска и передачи внешнего контекста, а Memory — концепция сохранения и использования информации агентом.

### 20.4. Planning — планирование

Планировщик разбивает сложную задачу на отдельные этапы.

Например:

```
Задача:
Исследовать подозрительный IP.

План:
1. Получить информацию об IP.
2. Проверить репутацию.
3. Найти связанные IOC.
4. Проверить внутренние логи.
5. Сопоставить с Threat Intelligence.
6. Сформировать отчёт.
```

### 20.5. Reflection / Error Handling

Механизмы проверки результатов и обработки ошибок.

Агент может:

- Проверять результаты инструментов.
    
- Обнаруживать отсутствие данных.
    
- Повторять запрос.
    
- Менять стратегию.
    
- Корректировать план.
    

### 20.6. Environment — окружение

Внешняя среда, с которой взаимодействует агент.

Например:

- Операционная система.
    
- Сеть.
    
- SIEM.
    
- API.
    
- База данных.
    
- Файловая система.
    
- Облачная инфраструктура.
    

## 21. ReAct Pattern

ReAct (Reasoning + Acting) — паттерн, объединяющий рассуждение модели и выполнение действий.

Основной цикл:

```
        USER TASK
            |
            v
         REASON
   Определение следующего шага
            |
            v
          ACT
     Вызов инструмента
            |
            v
        OBSERVE
     Получение результата
            |
            v
      EVALUATE RESULT
            |
       +----+----+
       |         |
     DONE      CONTINUE
       |         |
       v         v
    ANSWER     REASON
```

Три ключевых элемента:

**Reason** — модель определяет, что необходимо сделать.

**Act** — агент выполняет действие через инструмент.

**Observe** — агент получает результат и использует его для следующего шага.

Цикл повторяется до достижения цели или завершения процесса.

Преимущества:

- Многошаговое выполнение задач.
    
- Использование внешних инструментов.
    
- Возможность учитывать результаты предыдущих действий.
    
- Более управляемый процесс выполнения.
    

Важно: видимые промежуточные сообщения не обязательно являются полным или достоверным отображением внутренних рассуждений модели.

## 22. Multi-Agent Systems (MAS)

Multi-Agent System — система, состоящая из нескольких специализированных AI-агентов, которые совместно решают одну задачу.

Вместо одного универсального агента используются отдельные исполнители с разными ролями.

Пример архитектуры:

```
             USER TASK
                 |
                 v
          ORCHESTRATOR
                 |
       +---------+---------+
       |         |         |
       v         v         v
   RESEARCHER  ANALYST  EXECUTOR
       |         |         |
       +---------+---------+
                 |
                 v
             VALIDATOR
                 |
                 v
             FINAL RESULT
```

Примеры ролей:

**Orchestrator**

- Получает задачу.
    
- Разбивает её на подзадачи.
    
- Распределяет работу.
    
- Собирает результаты.
    

**Researcher**

- Ищет информацию.
    
- Изучает источники.
    
- Собирает данные.
    

**Analyst**

- Анализирует результаты.
    
- Сопоставляет факты.
    
- Формирует выводы.
    

**Executor**

- Выполняет необходимые действия.
    

**Validator**

- Проверяет результаты.
    
- Ищет противоречия.
    
- Оценивает качество.
    

### Преимущества MAS

- Параллельное выполнение задач.
    
- Разделение ответственности.
    
- Специализация агентов.
    
- Возможность взаимной проверки результатов.
    
- Масштабирование сложных процессов.
    

### Недостатки MAS

- Увеличение затрат на токены и вычисления.
    
- Сложность координации.
    
- Возможность противоречий.
    
- Сложность отладки.
    
- Расширение поверхности атаки.

## 24. Протоколы взаимодействия агентов и инструментов

Отдельное внимание следует уделить MCP (Model Context Protocol).

MCP — протокол, позволяющий AI-приложениям подключаться к внешним источникам данных и инструментам через стандартизированный интерфейс.

Он упрощает интеграцию моделей и агентов с:

- Файловыми системами.
    
- Базами данных.
    
- API.
    
- Внешними сервисами.
    
- Инструментами разработки.
    

MCP не является самостоятельным агентным фреймворком и не заменяет логику планирования или выполнения задач.

## 25. Практический пример AI Agent

В статье реализован минимальный AI-агент-помощник с использованием Python, LangChain, Qwen и Ollama.

Пример включает три инструмента:

|Tool|Назначение|
|---|---|
|get_weather|Получение информации о погоде|
|get_events|Получение информации о мероприятиях|
|send_email|Формирование и отправка письма|

Основные компоненты реализации:

**1. Model Initialization**

Инициализация языковой модели Qwen через Ollama.

**2. Tools**

Определение функций, доступных агенту.

**3. System Prompt**

Описание роли агента, его инструментов и правил поведения.

**4. Agent Creation**

Передача модели и инструментов в механизм создания агента.

**5. Execution Loop**

Получение запроса, выполнение действий и обработка результатов.

Упрощённая схема:

```
USER REQUEST
     |
     v
SYSTEM PROMPT + CONTEXT
     |
     v
      LLM
     |
     v
TOOL SELECTION
     |
     v
TOOL EXECUTION
     |
     v
TOOL RESULT
     |
     v
   LLM
     |
     v
FINAL RESPONSE
```

Ключевой момент: модель не выполняет функции самостоятельно. Она выбирает доступный инструмент и формирует аргументы вызова, а реальное выполнение происходит в программном окружении.

### Security Analysis практического примера

Даже простой агент создаёт несколько потенциальных точек риска.

|Компонент|Потенциальный риск|
|---|---|
|System Prompt|Prompt Injection|
|User Context|Утечка персональных данных|
|Tools|Tool Abuse|
|API|Несанкционированный доступ|
|Memory|Memory Poisoning|
|Execution Loop|Неконтролируемое выполнение|
|Email Tool|Несанкционированные внешние действия|

Основные меры защиты:

1. Принцип Least Privilege.
    
2. Проверка аргументов инструментов.
    
3. Разделение прав доступа.
    
4. Подтверждение критичных действий человеком.
    
5. Ограничение количества итераций.
    
6. Логирование вызовов инструментов.
    
7. Контроль внешних источников данных.

# PART 6. ИТОГОВАЯ КАРТИНА

## 27. Как связаны все четыре технологии

|Технология|Ключевой вопрос|
|---|---|
|LLM|Как система обрабатывает и генерирует информацию?|
|Prompt Engineering|Как управлять поведением модели?|
|RAG|Как предоставить модели внешние знания?|
|AI Agent|Как заставить систему выполнять действия для достижения цели?|

Пример комплексной AI-системы для SOC:

```
                SOC ANALYST
                     |
                     v
               AI INTERFACE
                     |
                     v
              PROMPT ENGINEERING
                     |
                     v
                    LLM
                     |
           +---------+---------+
           |                   |
           v                   v
          RAG               AI AGENT
           |                   |
           v                   v
      SOC KNOWLEDGE         PLANNING
      MITRE ATT&CK              |
      Runbooks                  v
      Incident Reports       TOOL CALLING
                                |
                +---------------+---------------+
                |               |               |
                v               v               v
               SIEM            EDR             CTI
                |               |               |
                +---------------+---------------+
                                |
                                v
                         RESULT VALIDATION
                                |
                                v
                           SOC REPORT
                                |
                                v
                         HUMAN APPROVAL
```

В этой архитектуре:

- LLM обеспечивает обработку информации.
    
- Prompt Engineering задаёт правила и формат работы.
    
- RAG предоставляет внутренние знания.
    
- AI Agent управляет последовательностью действий.
    
- Инструменты обеспечивают взаимодействие с инфраструктурой.
    
- Человек контролирует критичные операции.
    

## 28. Главные выводы

1. LLM — это фундамент современных генеративных AI-систем.
    
2. Prompt Engineering позволяет управлять поведением модели, но не гарантирует достоверность ответов.
    
3. RAG расширяет возможности LLM за счёт подключения внешних источников знаний.
    
4. AI Agents позволяют перейти от генерации текста к многошаговому выполнению задач.
    
5. Multi-Agent Systems позволяют разделять сложные задачи между специализированными агентами.
    
6. Каждый дополнительный компонент расширяет функциональность, но одновременно может увеличивать поверхность атаки.
    
7. Безопасность AI-систем должна обеспечиваться архитектурными и программными механизмами, а не только инструкциями в системном промпте.
    

**Главная мысль:** чтобы понимать безопасность AI-агентов, необходимо сначала понимать, как работают LLM, как управляется их поведение, как подключаются внешние знания и как организуется выполнение действий.
